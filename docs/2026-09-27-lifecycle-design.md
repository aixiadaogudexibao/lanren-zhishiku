# 条目生命周期（衰减与用户裁决）

日期：2026-09-27
状态：已实施
关联任务：planing-biao / pk-002（对应 G2）
> 本文记录来自作者本机环境；文中的领域名、案例号、条目计数已做脱敏。


## 背景与待解问题

pk-001 让实战使用变成可查询的事实（`yongfa.txt`）。pk-002 要在此基础上回答：**什么该退休、谁来拍板。**

初版设计里有两个问题：

1. **「零使用」没有信息量。** 首次启用时整个库都没被用过，于是一次性报出「全库零使用」——这不是「它们都没用」，而是「还没人用过」。拿它当判据会一口气标废全库。
2. **没有任何计数能表达「多久没人用」。** `命中` 是来源支撑数，`用N` 是累计次数；一个 3 年前用过一次、此后无人问津的条目，和昨天刚用过的条目，在数据上长得一样。

## 决策

### 1. 结果只有两态

「部分」废除：判不准就记 `败`。中间态会让统计和判读都变模糊。

### 2. 引入生命周期：一个按「轮次」倒计时

- 单位是**轮次**：`chuli` 处理完一个任务 = 一轮。
- 满值 `L`（默认 3）。
- 本轮**用到** → 生命周期 = `L`；本轮**没用** → −1。
- 库里存在但表里没有的键（新建 / 首次见到）→ 初始化为 `L`。
- **空轮次也要记账** —— 不记账，生命周期就不动，机制形同虚设。

这条同时解掉上面两个问题：首次启用时全部初始化为 `L`，要 `L` 轮真实任务之后才可能归零；而「连续 `L` 轮没人用」本身就是「多久没人用」的表达。

### 3. 归零 = 询问用户，不是自动处置

- 生命周期降到 `0` → 状态 `待裁决` → **必须询问用户**。
- 用户**同意**已无用 → `--expire`：状态 `已裁决:过期`，**冻结**（不再倒计时、不重复问）；由 `gengxin` 下次回注时在对应条目落 `[候选过期]` 标记。
- 用户**不同意** → `--refresh`：**生命周期刷新回 `L`**，回到观察期。
- 没有用户答复 → 什么都不写，停在 `待裁决`，下次再问。
- **删除永远由用户手动做**（`gengxin` 铁律「不删条目」不变）。

「刷新」是这套设计的关键：用户说「这条还有用」就重置倒计时，而不是留一个永久豁免——过 `L` 轮还是没人用，会再问一次。

### 4. 汇总提问，不逐条连问

首次启用时归零可能一次上百条。规则：**列前 10 条 + 总数，汇总成一次问**——「全部标记过期 / 全部保留刷新 / 只处理某几条」。用户答保留 → 批量 `--refresh`。

### 5. 状态表：`shengming.txt`（维护型）

```
# 轮次：12
# 满值：3
# 键 | 生命周期 | 最后使用 | 状态
liucheng_biao/H.leak.3 | 3 | 2026-09-27 | 活跃
liucheng_biao/H.old.1 | 0 | 2026-08-01 | 待裁决
liucheng_biao/H.dead.1 | 0 | 2026-07-12 | 已裁决:过期
```

为什么不是 append-only、为什么不是写进条目里：

- **写进条目里**（每张卡加一个 `生命周期` 字段）更直观，但 `chuli` 每轮要改上百个文件，直接冲垮「chuli 只碰日志、不碰知识条目」的写权限边界。
- **纯派生**（不加状态文件，现算）看着最优雅，但**无法知道条目何时被引入**：新建的卡会被当成「一直没人用」，立刻扣到 0，误判新条目。
- **维护型状态表**折中：一个文件、`chuli` 每轮只改它；新键懒初始化，天然解决「新条目」问题；内容可从 `yongfa.txt` + 后续轮次重建。

写入只能经 `zhishiku-gengxin/scripts/yongfa.py`（`--tick` / `--refresh` / `--expire`），不手改——`★` 哨兵与状态迁移都由脚本负责，避免手工编辑写坏。

## 两种「该退休」的信号

| 信号 | 依据 | 观察期 |
|---|---|---|
| `成=0 且 败>=2` | 确定的失败证据 | 不需要，立刻可报 |
| 生命周期归零 | 连续 `L` 轮没人用 | 需要（靠轮次累积） |

两者都只产出「候选」；同意后也只写标记，不删条目。

## 已知取舍

- **首次启用会一次性归零全库**（作者的库是上百个键的量级）。这是「之前没有使用数据」的必然结果，不是判据错误；靠 `L` 轮观察期 + 汇总提问缓解。首次的那次汇总询问，实际含义更接近「先给全库定个基线」，用户答「全部保留刷新」即可。
- 生命周期不区分「键在库里但总览没挂上」这种情况，因此 `用0` 仍需人工查树，不能直接判死。
