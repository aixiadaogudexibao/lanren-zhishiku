# 判别条件：成功与失败成对提炼

日期：2026-09-27
状态：已实施
关联任务：planing-biao / pk-004（对应 G3）
> 本文记录来自作者本机环境；文中的领域名、案例号、条目计数已做脱敏。


## 背景

`tilian` 原本产出四类：知识点、执行流模板、错误处理、常用指令表。

问题在于：**知识点和错误处理是分开提炼的，谁也不知道「什么时候该走哪条路」。**

- `liucheng` 里画了树、留了 `├─` 分叉，但分叉旁的〔条件〕往往写不出来 —— 因为从单个案例里看不出分歧点在哪；
- `cuowu` 里记了坑（「glibc 2.35 下 `__malloc_hook` 失效」），但它和「该用 FSOP」这条路线之间没有连线；
- 结果是 `chuli` 走到分叉时，只能靠 agent 现场猜条件 —— 树形执行流的价值打折。

对照开源方案（ExpeL 的 contrastive insight、Agent Workflow Memory 的工作流归纳），缺的正是**对照式提炼**：把同一操作的成功与失败放在一起看，差异本身才是知识。

## 决策

新增**第五类产出：判别条件** → `tilian_wei/<领域>/panduan/<主题>.txt`。

### 触发（满足其一）

- 同一 `操作 + 指令` 在不同案例里既有成功又有失败；
- 同一「目的」下出现多条路线，而 `liucheng/` 没写清什么时候走哪条；
- `cuowu/<错误特征>` 的「适用」字段，正好是 `liucheng/<目的>` 某步骤该写的「条件」。

### 格式

```text
# <主题>（判别条件）

判别：<要做的决定，一句话>
条件 | 走哪枝 | 依据
<条件表达式> | <枝 / 做法> | <领域>/<案例id> buzou/<NN>.txt 步骤<x>（成）
<条件表达式> | <枝 / 做法> | <领域>/<案例id> buzou/<NN>.txt 步骤<y>（败）
默认 | <兜底做法> | —

来源：<领域>/<id1>（成）, <领域>/<id2>（败）
```

### 硬规矩（写进 SKILL.md）

1. **必须有「成」「败」两侧来源**。只有单侧的，那是知识点或错误处理，不是判别条件。
2. **条件必须可判定**：题面 / 运行环境里能直接观察的量（glibc 版本、保护位、有无 `anti-hook`、菜单索引上限、`seccomp` 是否拦 `open`）。**不写**「如果不行」「视情况」。
3. **必须给「默认」行**：条件全不命中时走哪条路，否则下游会出现「无路可走的分叉」。
4. 一个主题一个文件；同主题再次提炼补条件行、提高 `依据` 精度，**不新开文件**。
5. 判不出条件的写 `条件：待补` 并留空，**不要编**。

## 回注落点（gengxin 侧）

| 来源 | 落到哪 |
|---|---|
| `panduan/*.txt` 的每一行「条件 → 走哪枝」 | `liucheng.txt` 对应分叉旁的〔条件〕 |
| 同一行 | 该枝首张卡片 `liucheng_biao/<标号>.txt` 的 `## 条件` |
| 「默认」行 | 卡片 `## 不满足时` 或树的兜底枝 |

并加了一条硬约束：**`panduan/` 没有「默认」行 → 标 `待补条件` 并报告，不得让分叉无路可走**。
