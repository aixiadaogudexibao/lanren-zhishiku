反证结论：

| 结论 | 动作 |
|---|---|
| 未读 / 选错分叉 | **不标 1**；先读或改路由 |

| 纯复用已有卡且条件满足 | 保持 **0**；但须写明近似卡号 |

## **WP 专项判定（本轮用过 wp 时 MUST 先过这张表）**：

| 本轮 wp 情况 | 反证重点 | 典型结论 |
|---|---|---|
| wp 复现成功，库内无卡 | 读过=`liucheng_biao` 全扫 + `rg` 题干关键词；对不上=无任一卡覆盖此洞型 | **标 1**，层 `卡片`，码 `K-无卡` |
| wp 复现成功，库内有近似卡但参数不同 | 对不上=卡条件/尺寸/保护不符 | **标 1**，层 `参数`，码 `P-参数/布局` |
| wp 与本机不同（保护/libc/去符号），靠库修正做通 | 近似=相关的 `P-` 卡 | **标 1**，缺的是「对照公开题需重核」类说明 |
| wp 与本机不同，库内已有完整对应卡 | 近似=该卡号 | **保持 0**，写「库内覆盖：<卡号>」 |
| wp 找到但**未复现**、改用库内路做通 | 读过=库内路卡；对不上=库内路未记该坑 | **标 1**（缺的是库内路的坑） |
| wp 全失败/无网 | 照常反证 | 不得拿「wp 没有」当不采的理由 |

动作（处理中，顺序固定）：

1. **留下采集标记 = 写本 skill `xinxi.txt`**（禁止只放在会话记忆；报告前不得丢、压缩后不得装没有）。
   - 打开/定位**当前任务节**；把该节写成：
     ```text
     任务：<名>
     caiji标记：1
     ```
     （同节内保留领域/原路径/状态/明细等字段，见上「本 skill 的 xinxi.txt」。）
   - 每条 `标记明细` **卡住当下**至少含（方案 A）：
     - `层`：路由 | 卡片 | 参数 | 指令 | 错误 | 纠正（只选一）
     - `缺什么`：类型码 T/K/P/Z/E/U/C（只选一）
     - `何时`：卡在哪一步 / 哪张卡 / 哪个分叉
     - `反证`：读过=…；对不上=…；选错分叉=是|否；近似=…|-
     - `差在`：与近似的一句差异；无近似写「无近似，缺整段」
     - `当时判断`：agent 原打算怎么做
     - `用户原话`：纠正类必填原话；否则 `-`
     - `如何越过`：**越过后补写**（办法 / skill / 关键命令要点）——**不要**用事后总结改写「缺什么/差在」
   - `标记摘要` 建议：`层:<层> | <类型码> | <一句差在>`
   - 同步续跑条：`采集标记` 条数、`标记摘要` 与本文件一致（摘要可带层）。
2. **禁止在步骤 5 调用 `zhishiku-caiji`**。处理阶段只做任务，采集挪到步骤 6。
3. **扫描可用 skill 辅助越过缺口**（与是否采集无关，为了做完题）：
   - 读 skill 索引 `skills.jsonl`（或 `skill-manager` 查询）。路径：Windows `C:\Users\<用户>\.pi\agent\skill-index\skills.jsonl`，Linux/WSL `/mnt/c/Users/<用户>/.pi/agent/skill-index/skills.jsonl`；索引不可用则扫 skills 根目录各 `SKILL.md` 的 `description`。
   - 按关键词匹配 → 读最匹配 skill 的流程来解决。
   - 无匹配 → 用通用能力继续，并在 `xinxi.txt` 明细与报告写「无 skill 可辅助」。
4. **缺口越过后立刻回到 chuli 主流程**，继续按知识库做后续步骤——**不得停在别的 skill 里**；越过方式**只补写**该条明细的「如何越过」，不改已写的层/类型码/差在（除非反证证明 initially 定层错误，更正时注明）。
5. 同一类缺口反复出现 → **合并/更新 `xinxi.txt` 同一条明细**（同类 = 同层 + 同类型码 + 同近似或同何时锚点），不要无信息重复堆多条；不同缺口分别一条明细；只要存在任一条未清缺口 → `caiji标记` 保持 **1**。
6. 纯复用已有思路、全程无上述缺口（或反证显示仅选错分叉已纠正）→ **`caiji标记` 保持 0**（不要为形式改成 1）；完成后**直接把结果交给用户**，不调 caiji；收尾把该任务节闭掉。
