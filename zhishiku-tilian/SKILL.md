# 知识库提炼（zhishiku-tilian）

## 概述

本 skill 是 `zhishiku-caiji` 的**下游**：上游采集原始案例轨迹，这里把轨迹**提炼**成可复用知识。

**产物是知识，不是第二个案例库。** 每条产出必须比原始样本更抽象、更可复用，并且能溯源回样本。把案例原文抄进知识库 ≠ 提炼。

## 下游用途（为 AI 设计 skill）

提炼出来的东西**是给 AI 写 skill 用的素材**，不是给人看的笔记。每条产出最终会落到某个新 SKILL.md 的固定位置：

| 提炼产出 | 在新 skill 里变成 |
|---|---|
| 知识点 | 铁律 / 概述原则 / 常见错误 |
| 执行流模板 | 协议步骤 / Quick Reference |
| 错误处理 | 常见错误表 / 合理化表 / 排查段 |
| 常用指令表 | 命令速查 / Implementation |
| 「本案例特有 / 不适用」 | 「何时用 / 何时不用」的边界 |

因此产出必须**面向 skill 编制**：

- 字段固定、一行一个要点，带 `归属` 标记（写清它属于新 skill 的哪一节）。
- 失败用固定三段式 `现象 / 原因 / 处理`，可直接搬进「常见错误表」。
- 抽象到「可复用」为止：既不能写死具体路径，也不能空泛到无法执行。
- 宁可多写一条具体规则，不写一句无法落地的口号。

## 流水线定位

```text
执行任务 ──▶ zhishiku-caiji（采集） ──▶ 案例文件夹 ──▶ zhishiku-tilian（提炼） ──▶ 知识库
                                                          ├─ 知识点
                                                          ├─ 执行流模板
                                                          ├─ 错误处理
                                                          └─ 常用指令表
                                             提炼完成后链式调用 ▼
                                        zhishiku-gengxin（按领域回注到容器）
```

| 需求 | 用哪个 |
|---|---|
| 小任务队列 / 每日任务 / 执行次数 | `planing-biao` |
| 长跑项目 / 需求 / issue / 迭代 | `chang-plan` |
| 执行过程留痕、采集案例 | `zhishiku-caiji` |
| **把案例提炼成知识点 / 执行流 / 错误处理** | **本 skill** |

## 输入

从 `zhishiku-caiji` 的数据根**按领域**读取案例：

```text
<caiji_wei>/<领域>/
  ├─ biao_xin.txt
  └─ biao/{dai,hui}/<编号>/
       ├─ renwu.txt        # 案例目标、边界、领域
       ├─ qingdan.txt      # 大步骤清单（执行流的骨架）
       └─ buzou/<NN>.txt   # 内含 `->` 块（提炼原料）
```

- 数据根来源：读 `zhishiku-caiji` 的 `xinxi.txt`（键 `caiji_wei`）；读不到就问用户。
- **领域**：默认取案例 `renwu.txt` 的 `领域：` 字段；缺失则**询问用户**，不得臆断。
- 可以只提炼一个领域，也可一次处理多个领域；但**每个领域的结果分别写进自己的库**。

## 输出布局（按领域分库）

```text
<skill 目录>/xinxi.txt        # 每个数据根两行：tilian_wei_win / tilian_wei_linux
<tilian_wei>/<领域>/          # 一个领域 = 一个库 = 一个文件夹
  ├─ zhishi/<主题>.txt        # 知识点
  ├─ liucheng/<目的>.txt      # 执行流模板
  ├─ cuowu/<错误特征>.txt     # 错误处理
  ├─ zhilingbiao.txt          # 常用指令表（维护型表格）
  ├─ renlei/                   # 人类阅读版（可选，必须先询问才生成）
  └─ suoyin.txt               # 领域提炼索引（append-only，末尾 ★）
```

- 领域库名与 `zhishiku-caiji` 的领域名**一致**；下游 `zhishiku-gengxin` 也用同一个领域名。

**跨平台路径解析（MUST）**：`xinxi.txt` 为每个数据根保留**两行**，指向**同一个文件夹**：

```text
tilian_wei_win: <Windows 数据根绝对路径>
tilian_wei_linux: <Linux 数据根绝对路径>
```

按当前运行环境选取：

- **Windows** → 取 `tilian_wei_win`（形如 `C:/Users/xi/.pi/agent/skills/...`）。
- **Linux**（含 WSL）→ 取 `tilian_wei_linux`（形如 `/media/xi/系统/Users/xi/.pi/agent/skills/...`）。
- 旧单行 `<根名>: <路径>` → 按当前 OS 判断；不可访问则询问用户补写另一平台路径。

两行必须指向同一份数据根；不一致 → 停下询问。缺失/为空 → 询问用户后初始化（默认 `<skill 目录>/tilian_wei/`），并把两平台路径写入 `xinxi.txt`。

## 提炼原料：`->` 块

每个块是一条样本，形状固定：

```text
-> <操作>
   位置：<终端/浏览器/文件>
   指令：<完整命令或交互>
   结果：<实际输出>
   结论：<判断>
```

四类产出都从这些块里来；**不得引入案例之外的知识**。

## 四类产出与提炼规则

### 1. 知识点 → `zhishi/<主题>.txt`

从 `结论`（必要时结合 `结果`）抽取**可复用的一般性陈述**。按主题归一个文件。

```text
# <主题>

<要点一句话>
  归属：铁律 | 概述原则 | 常见错误 | 边界
  来源：<领域>/<案例id> buzou/<NN>.txt 步骤<字母>
  命中：<N>

<要点一句话>
  归属：...
  来源：...
  命中：<N>
```

- 同一主题的要点合并进同一文件；重复要点不新增，把 `命中` 加一。
- 实在无法一般化的（本案例特有）→ 标注「本案例特有」，不要硬拔高，也不丢弃。

### 2. 执行流模板 → `liucheng/<目的>.txt`（供 gengxin 回注为树 + 卡片）

把操作序列抽象成**带参数的步骤**；`指令` 作为实例保留。**模板按「技术」组织，不按「题目」组织。**

下游 `zhishiku-gengxin` 会把本文件回注成：
- `liucheng.txt` 上的一棵（或一段）**树**；
- `liucheng_biao/<标号>.txt` **一步一卡**。

因此 tilian 产出必须让人/agent 能看出：**顺序、分叉条件、每步时机**。推荐两种等价写法（可并存）：

**写法 A · 竖排步骤（兼容）**

```text
# <目的>（技术名，不是题目名）
分类：通用 | 堆 | 栈 | 格式化串 | 其他

1. <抽象操作>（参数：<占位符>）
   时机：<何时做>
   条件：<必须满足；不满足则 → 分支/跳过>
   实例：<具体指令>
   来源：<领域>/<案例id> buzou/<NN>.txt 步骤<字母>
2. ...
```

**写法 B · 预标号（优先，少一层 gengxin 猜号）**

```text
# <目的>
分类：堆
树：H.leak   # 或新建树名

H.leak.1 布局
  时机：...
  条件：...
  不满足时：...
  做什么：...（参数：<>）
  实例：...
  下一跳：H.leak.2
  来源：...
```

**硬规矩：**

1. **一个模板只讲一个技术**。不要把「AL 截断 + strcpy 补 NUL + ROP」糅成一条；拆成独立模板。
2. **模板名用技术/目的，不用题目名**。
3. **公共步骤**标成通用 / `T.*`，其它模板只引用。
4. **具体数值一律参数化**：地址 / 尺寸 / 偏移 → `<占位符>`；具体值只放「实例」。
5. **分叉必须写条件**（有无 anti-hook、free 哪个 idx、glibc 版本…），方便 gengxin 画 `├─` 枝。
6. 同一「目的」多案例 → 差异写**分支**，不新增平行模板。

- 抽象掉具体路径、文件名、版本号。
- 保留顺序与依赖；跳过的大步骤注明「可跳过：<条件>」。

### 3. 错误处理 → `cuowu/<错误特征>.txt`

从 `结果` 命中失败特征的块提炼。失败特征包括：非零退出码、`error` / `failed` / `not found` / `permission denied` / `traceback` / 超时 / 被拒绝 / 明确报错。

```text
# <错误特征>

现象：<结果原文摘要>
原因：<结论给出的判断>
处理：<结论给出的修复；若结论没给，标注「结论未给出处理」>
适用：<前提条件>
归属：常见错误表 | 合理化表 | 排查段
来源：<领域>/<案例id> buzou/<NN>.txt 步骤<字母>
```

**失败路径必须提炼，不得只收成功路径。** 失败定义了坑在哪，是知识库里最值钱的部分。

### 4. 常用指令表 → `zhilingbiao.txt`

聚合 `(操作, 位置, 指令)`，等价变体归一：

```text
操作 | 位置 | 指令（规范形式） | 命中
搜索本地软件 | 终端 | which <软件> | 3
解压压缩包 | 终端 | tar -xzf <包> -C <目录> | 1
```

- 同一 `操作+指令` 只保留一行；再次命中把 `命中` 加一。
- 这是**维护型表格**（允许改写计数行），不做 append-only；`★` 只用于 `suoyin.txt`。

### 5. 人类阅读版 → `renlei/<主题或案例>.md`（可选，须先询问）

前四类产出面向 AI 编制 skill（字段化、机器可读）。如果用户本人也要读，可在**询问后额外**整理一份人类版。

**必须先问，不许默认生成。** 完成四类产出后单独问一句：

> 「要不要再整理一份给人读的版本？（按案例或按主题）」

- 用户说要 → 写 `renlei/`；说不要或没回应 → 只留机器可读版，并在报告里注明「未生成人类版（未确认）」。
- **必须放在 `renlei/` 目录下**（可 `.md` 或 `.txt`），不得写到知识库根或别处。
- 人类版面向阅读：允许连续叙述、章节标题、必要解释，把知识点 / 执行流 / 错误处理按主题串成一篇。
- 人类版**不替代**四类产出，也不反向影响它们；两者各自独立。
- 非交互执行：若任务描述已明确要或不要，按描述；否则默认**不生成**，不得自作主张写入。

## 索引 → `suoyin.txt`（append-only，末尾 ★）

每提炼一个案例，追加一行，记录它产出了什么：

```text
# 案例id | 产出文件 | 要点数
0001 | zhishi/qq安装.txt, cuowu/命令未找到.txt | 3
★
```

追加 = 一次替换，不读全文：

```text
Edit: oldText = "★"
      newText = "<新行>\n★"
```

## 铁律（MUST）

1. **不得臆造**：只提炼案例里真实出现过的内容；案例里没有的不写。
2. **每条产出必须溯源**：`来源：<领域>/<案例id> buzou/<NN>.txt 步骤<字母>`，且该来源必须真实存在。
3. **失败路径必须提炼**，不得只收成功路径。
4. **幂等增量**：同一案例重新提炼只更新/合并，不重复添加；重跑不改计数之外的内容。
5. **抽象要保留参数**：模板用占位符，不写死具体路径/名称。
6. **知识库不是第二个案例库**：不得把原始输出原文大段抄入；必须归纳。
7. **禁止本地模型参与本 skill（防污染）**：Ollama / 本地 LLM 会话**不得**跑提炼、改 `tilian_wei`、代写归属或「润色」知识点。本地模型仅允许 `zhishiku-chuli` + `ctf-pwn`；本 skill 与 `caiji`/`gengxin` 在本地模型模式下**一律禁用**。若当前是本地模型会话 → **停止并报告「tilian 已禁用（本地模型模式）」**，不得写盘。

## 协议

```text
- [ ] 1. 确定数据根与领域（caiji_wei / tilian_wei / 领域）
- [ ] 2. 选案例（默认 dai + hui 全量，或用户指定）
- [ ] 3. 解析 `->` 块
- [ ] 4. 产出四类条目（知识点 / 执行流 / 错误处理 / 常用指令表）
- [ ] 5. 更新索引 suoyin.txt
- [ ] 6. 询问是否生成人类阅读版（可选，默认不生成）
- [ ] 7. 报告新增 / 合并 / 跳过
- [ ] 8. 回注：调用 zhishiku-gengxin 按领域写入容器
```

**1. 确定数据根与领域**：读 `zhishiku-caiji/xinxi.txt` 按当前 OS 拿 `caiji_wei`（`_win` / `_linux`）；`tilian_wei` 同理取当前 OS 对应行，缺失则初始化；领域取案例 `renwu.txt` 的 `领域：`，缺失则询问用户。

**2. 选案例**：默认 `biao/dai` + `biao/hui` 全部；用户指定则只处理指定编号。

**3. 解析**：逐 `buzou/NN.txt` 读取 `->` 块，记录（操作, 位置, 指令, 结果, 结论, 来源）。

**4. 产出**：按上面四类规则写入；已存在的条目走合并/计数。

**5. 索引**：往 `suoyin.txt` 哨兵处追加一行。

**6. 人类阅读版（可选）**：先问用户要不要；要则写 `renlei/`，不要或没回应则跳过，并在报告注明「未生成人类版（未确认）」。**不得默认生成。**

**7. 报告**：新增 N 条 / 合并 M 条 / 跳过 K 条，并列出产出文件（含是否生成了人类版）。

**8. 回注（链式）**：报告后，调用 `zhishiku-gengxin`，把领域库（`tilian_wei/<领域>`）回注到知识容器 `gengxin_wei/<领域>/`。

- 领域**沿用本次提炼的领域**（来自案例 `renwu.txt` 的 `领域：`）；本 skill 不另猜、不换名。
- 领域缺失（案例没标且用户没给）→ 由 gengxin **询问用户**。
- 非交互且领域未定：gengxin 只报告「待回注知识 + 建议领域」不写入——**预期行为**，不是失败。
- gengxin 不可用 → 跳过并注明「未回注」；回注失败不影响本次提炼结果。

## 提炼节奏

**一个案例一次提炼，逐条产出、逐条溯源。** 不得先通读全部案例、最后一次性编造一份漂亮总结——那会丢掉来源对应关系。

### 为什么会想走捷径（必须识破的借口）

| 借口 | 现实 |
|---|---|
| 这条结论太具体，提炼不出来 | 具体结论也能归纳；真不能就标「本案例特有」，别硬拔高，也别丢 |
| 报错只是我手误，不算知识 | 手误也是坑；错误处理的价值正在这里 |
| 指令是随手写的，不用进表 | 随手写的指令正是常用指令表的来源 |
| 先全抄进知识库，以后再整理 | 那是第二个案例库，不是知识库；抄 = 没提炼 |
| 那个案例没跑成功，跳过吧 | 失败路径最值钱；跳过 = 丢知识点 |
| 来源太长，省了 | 没来源的知识无法反查，等于谣言 |

### 红旗（出现任意一条，立即停下修正）

- 我写的内容案例里没有。
- 我写了一条产出却没有 `来源`。
- 我只提炼了成功路径。
- 我把原始输出大段抄进了知识库。
- 我准备「通读全部案例后一次性总结」，而不是逐案例逐条产出。
- **我在本地模型模式下提炼，或让 Ollama 生成/改写 tilian_wei 条目。**

## 启动自检

提炼前/后校验：

- 每条产出都有 `来源`，且 `来源` 指向的案例、文件、步骤字母都真实存在。
- `renlei/` 若存在，必须是在用户确认后才生成；未确认时不得存在。
- 四类产出里，`cuowu/` 非空（除非所有案例确实没出现过失败）。
- `zhilingbiao.txt` 无重复行（同 `操作+指令` 只有一行）。
- `suoyin.txt` 的产出列表与 `zhishi/` `liucheng/` `cuowu/` 实际文件一致。
- append-only 文件（`suoyin.txt`）末尾有且仅有一个 `★`。

## 示例

某案例的 `->` 块（节选）：

```text
-> 搜索本地软件
   位置：终端
   指令：which qq
   结果：which: no qq in (...)
   结论：PATH 中没有 qq，需安装或用绝对路径
-> 启动 qq
   位置：终端
   指令：qq
   结果：command not found
   结论：同因，PATH 未包含安装目录
```

提炼产出：

```text
# zhishi/命令查找.txt
which 只查 PATH，不查已安装但未入 PATH 的软件
  来源：0001 buzou/01.txt 步骤a
  命中：1
```

```text
# cuowu/命令未找到.txt
现象：which: no qq in (...)
原因：PATH 中没有 qq（已安装但未写入 PATH 的软件同样查不到）
处理：安装软件，或把安装目录加入 PATH / 用绝对路径调用
适用：Linux/macOS 终端
来源：0001 buzou/01.txt 步骤a
```

```text
# liucheng/启动本地软件.txt
1. 搜索软件（参数：<软件名>）
   实例：which qq
   来源：0001 buzou/01.txt 步骤a
2. 若搜索失败，安装或修正 PATH
   实例：<安装命令> / export PATH=...
   来源：0001 buzou/01.txt 步骤a
3. 启动（参数：<软件名>）
   实例：qq
   来源：0001 buzou/01.txt 步骤b
```

```text
# zhilingbiao.txt
操作 | 位置 | 指令（规范形式） | 命中
搜索本地软件 | 终端 | which <软件> | 1
启动程序 | 终端 | <程序名> | 1
```

## 常见错误

| 错误 | 后果 | 纠正 |
|---|---|---|
| 臆造案例里没有的知识 | 知识库失真 | 只提炼出现过的内容 |
| 缺来源 | 无法反查、无法信任 | 每条产出写 `来源` |
| 只提炼成功路径 | 丢掉最值钱的错误处理 | 失败块必须提炼 |
